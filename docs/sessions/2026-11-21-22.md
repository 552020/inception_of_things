## Machines and storage

The VM lives as one compressed disk in sgoinfre; every new seat copies it to goinfre and starts it from there. On 28 November the seat c1b3c2 had an empty goinfre, so the VM has to be restored before any test.

| Seat | CPU | RAM | Used |
| --- | --- | --- | --- |
| c1b3c2 | i7-12700, 20 threads | 15 GB | 28 Nov |
| c3a1c7 | i7-13700, 24 threads, NVMe | 15 GB | 21 to 22 Nov |

Neither seat has 32 GB; RAM is the only constraint. Check a seat with `free -g` and `lscpu`.

| File | Where | Size | Note |
| --- | --- | --- | --- |
| VM backup `IoT.qcow2` | ~/sgoinfre/IoT | 16.8 GB, compressed | made 22 Nov 01:44, qemu-img check clean, byte-identical to the verified copy |
| Launch script `iot-kvm.sh` | ~/sgoinfre/IoT and docs/host-vm | 1.4 KB | window by default, `headless` for none |
| Running disk | ~/goinfre/VMs on the seat in use | about 31 GB | wiped when another user logs in at that seat |

sgoinfre holds 16 of its 30 GB and is purged after 6 months without use. The old VirtualBox VM is unregistered and its disk and the 24.04 ISO were deleted on 22 November.

Restore on a new seat:

```bash
mkdir -p ~/goinfre/VMs
cp ~/sgoinfre/IoT/IoT.qcow2 ~/sgoinfre/IoT/iot-kvm.sh ~/goinfre/VMs/
test -w /dev/kvm && ~/goinfre/VMs/iot-kvm.sh
ssh -p 2222 slombard@localhost
```

Start the VM only while the screen is unlocked. /dev/kvm is a seat permission that the login screen takes back when the screen locks; QEMU then fails with "Could not access KVM kernel module: Permission denied". A VM that is already running keeps the device, so locking afterwards is fine.

Refresh the backup after real changes inside the VM, with the VM shut down: `qemu-img convert -p -c -O qcow2 ~/goinfre/VMs/IoT.qcow2 ~/sgoinfre/IoT/IoT.qcow2` (about 6 minutes to compress, 3 to copy).

- The interface fix works: 192.168.56.110 sits on eth1, Flannel is up.

Never run: `make test` in p1 (so the worker joining is unconfirmed), Part 2, Part 3, the bonus. Next time, run `make watch` in p1 right after `make up`; it logs memory, pressure, disk and the K3s journal of the server every 15 s for five minutes.
